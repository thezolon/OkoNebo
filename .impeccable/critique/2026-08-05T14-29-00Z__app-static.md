## Design Specificity Verdict

**Partially grounded — a genuinely product-specific idea buried under category-interchangeable dashboard chrome. Roughly 40% specific, 60% boilerplate, and the specific parts are the least visually prominent.**

The real OkoNebo thinking is concentrated in three places, and all three are good: per-provider freshness thresholds derived from the configured refresh interval rather than magic constants (app.js:553-615); `locationImpactPlugin`, which marks on the hourly chart the moment an alert begins affecting Home vs Office (app.js:2933); and the PWS delta view differencing two stations on one property (app.js:2717). "When does this hit my house" is the question a home weather station exists to answer, and it is answered on the timeline. Nothing else in the category does that.

Everything around it is Grafana-with-a-radar. `--sidebar-w: 220px` / near-black `#070b10` / 13px system stack is the default dark-admin-panel look. No weather-derived signal reaches the chrome — no sky state, no severity-driven page mood, no diurnal shift.

The tell: METAR and tides are configurable providers in both first-run and admin (index.html:446, admin.html:199) with **zero rendering surface anywhere in the viewer**, while "Retry Pressure" gets a dedicated tile. The composition was driven by what the backend emits, not by what someone standing at a window wants to know.

**Deterministic scan:** `detect.mjs --json app/static` exited 2 with **9 findings** — 5 `side-tab`, 2 `flat-type-hierarchy`, 1 `layout-transition`, 1 `broken-image`. On verification, **4 genuine, 5 false positives**.

Genuine: `.alert-banner` side-tab referencing the never-defined `--alert-unknown` inside a dead block (style.css:1553); `.app-shell { transition: margin-top }` animating a layout property on the 100dvh root grid, firing exactly when a severe alert arrives (style.css:136); a raw `#ffc864` side-tab injected via innerHTML in admin.js:598; and `<img id="current-icon" src="">` (index.html:41), which browsers resolve to the document URL — fetching index.html as an image before the onerror handler exists.

False positives: the three `border-left` hits on `.alert-card` and `.timeline-item` are **not** decorative side-tabs — they are a functional NWS severity encoding, recolored per severity and redundantly backed by a background tint. Removing them would lose meaning. Both `flat-type-hierarchy` hits came from sampling only inline `style=` attributes and missing the linked stylesheet; the real scale runs 8→52px.

Notably, the detector missed the two largest structural defects: the 417-line dead stylesheet and the total absence of `prefers-reduced-motion`.

**Visual overlays:** none. No browser automation was exposed, so injection was never attempted and no user-visible overlay exists.

## Overall Impression

This is an ambitious, operationally mature dashboard that scores Poor because it is undisciplined, not because it is unambitious. Someone who understands weather data built the hard parts well — provenance, degraded-mode honesty, freshness modeling — and then let a superseded design rot in place underneath it while the interface accumulated every diagnostic the backend could emit.

The single biggest opportunity: **the product currently optimizes for explaining itself to its operator, not for answering its user's question.** Nine metric tiles, a retry-pressure meter, a cache-hit ratio, and an ops timeline all render. The NWS `instruction` field — the sentence that says "TAKE COVER NOW" — does not.

## What's Working

**1. Data provenance and freshness as first-class UI.** The current-conditions block flips between NWS / each PWS / OpenWeather / Auto Blend, remembers the choice, and shows a per-source age grid with provider-tuned thresholds. `getNwsObsHealth` derives its "questionable" threshold from your configured refresh interval instead of a constant (app.js:565). This is the app's actual idea and it is well engineered.

**2. Degraded-mode honesty.** State survives a reload with no network (app.js:1750). The frame cache gets an explicit 24h offline grace window with its own metric. The status pill reads `OFFLINE - Last synced 12m old` rather than spinning. Refresh is disabled *with a stated reason*. Firewatch preserves last-known-good and says so. For a Pi that loses wifi, this instinct is right throughout.

**3. Engineering discipline in the places that usually rot.** Zero layout thrashing in 4417 lines — no geometry reads at all. `escapeHtml()` defined once and applied at every innerHTML interpolation site across four upstream APIs. SRI hashes on CDN assets. `aria-expanded` declared *and* synchronized. Where ARIA is used it is used correctly; the failure is coverage, not competence.

## Priority Issues

### [P0] The alert response path drops the only actionable field
NWS ships an `instruction` on every warning — the text telling a person what to physically do. Verified: `instruction` appears exactly once in the codebase (app.js:1031), as a string literal inside the synthetic test alert. **No render path displays it.** Alert cards render event/severity/urgency/expires/coverage/description only (app.js:2569). A user reading OkoNebo during a tornado warning learns the event name and expiry, and not one word about taking shelter.
**Fix:** render `alert.instruction` above `alert.description`, unclamped, ≥14px, in a bordered `--sev-*` block; same in the map popup; make the ticker click through to it.
**Command:** `/impeccable harden`

### [P0] "Test Alert" ships an unmarked fake Tornado Warning in the primary toolbar
Verified: `getTestAlert()` returns `event: 'Tornado Warning', severity: 'Severe', synthetic: true` (app.js:1024). The card gets a "Test polygon" pill, but the ticker renders `alertBannerLabel()`, which returns the event uppercased with **no synthetic branch** (app.js:884). The full-width red ticker reads TORNADO WARNING. The loudest element on screen is the one that isn't marked. On a wall display, anyone walking past sees a real tornado warning.
**Fix:** move to admin; or prefix `TEST —`, force a neutral ticker tone for synthetic alerts, require confirmation.
**Command:** `/impeccable harden`

### [P0] Mobile amputates the controls that matter most on mobile
`style.css:1865-1867` hides `.source-carousel`, `.source-age-grid`, and the entire `.sidebar-controls` block below 700px — Units, Storm mode, interval, Refresh Now, and **Enable Severe Alert Push**. The push opt-in is unreachable on the only device that can receive push. Lines 1857-1858 also hide `.condition-desc` and `.feels-like`. Meanwhile the map keeps 240-420px while alerts get 100px (:1873). These are hidden, not relocated — there is no mobile-alternate markup.
**Fix:** bottom sheet or disclosure; keep `feels-like` and one freshness chip always visible; invert the height budget so alerts get ≥200px when non-empty.
**Command:** `/impeccable adapt`

### [P0] `--t3` fails contrast on every surface — that's the entire label layer
`--t3: #4a6278` measures 2.42:1 on `--bg-3`, 2.70:1 on `--bg-2`, 2.91:1 on `--bg-1`, 3.11:1 on `--bg-0`. AA needs 4.5:1. All of it is 8–11px so none qualifies for the large-text exception. It colors 19 classes — `.stat-lbl`, `.last-updated`, `.source-age-lbl`, `.pws-k`, `.hcell-time`, `.fc-desc`, `.no-alerts`, `.feels-like`, `.timeline-time` — i.e. the word half of every metric in the product. On a wall display at distance, or a phone in daylight, the labels are gone.
**Fix:** `#7c93aa` verified at 4.55:1 / 5.11:1 / 5.51:1 across the three backgrounds. One-line change, repairs 19 classes. Consider collapsing the 3-tier text ramp to 2 — `#7c93aa` is close to the existing `--t2`.
**Command:** `/impeccable polish`

### [P0] Alerts are unreachable by keyboard and silent to screen readers
`.alert-card` is a `<div>` with a click listener, `cursor:pointer`, and no `tabindex`, `role`, or keydown handler (app.js:2565). 30 click listeners in app.js; one keydown, for a Shift+C shortcut. Clicking is the only way to expand a warning past its 5-line clamp or zoom to its polygon. Separately `#alert-ticker` has no `role="alert"` and no `aria-live` (index.html:21) — a tornado warning appearing produces zero announcement. Both modals lack focus management: zero `focus()` calls and zero Escape handlers exist in app.js or admin.js, and `#auth-modal` has no `role="dialog"` at all.
**Fix:** `<button>` + `aria-expanded` on alert and fire cards; `role="alert"` on the ticker; `aria-live="polite"` on status pill and error toast; focus trap, Esc, and dialog semantics on both modals.
**Command:** `/impeccable harden`

### [P0] 20 undefined custom properties collide with live selectors
Referenced by 79 declarations. An unresolvable `var()` is invalid at computed-value time: non-inherited properties reset to initial, inherited ones fall back to `inherit`. Four live selectors are declared twice with the dead copy *later* at equal specificity, so it wins — `.status-pill` renders from the dead rule; `.last-updated` is 44% larger and brighter than designed; `.alerts-container` gap collapses to 0; `.alert-desc` loses its top margin. Lines 1739-1743 are literally commented "Fix cascade conflicts from legacy styles" — the collision was known and four symptoms were patched instead of the cause. `.status-pill`, `.last-updated`, and `.alerts-container` were missed by that patch and are broken today.
**Fix:** delete style.css:1317-1733 plus the 1739-1743 patch. Removes 20% of the stylesheet, eliminates all 20 undefined tokens, and repairs `.status-pill` and `.last-updated` for free. Verified: none of those ~40 class names appear in any HTML or JS template.
**Command:** `/impeccable polish`

### [P1] No `prefers-reduced-motion` anywhere in 2084 lines
Zero occurrences of `prefers-reduced-motion`, `prefers-contrast`, or `forced-colors`. Unhandled: a 30-second infinite marquee on the alert ticker (style.css:123), the radar animation loop, six transitions, a backdrop blur. A user with vestibular sensitivity gets a permanently scrolling banner during exactly the event they most need to read. The marquee also implicates 2.2.2 Pause/Stop/Hide — auto-scrolling text over 5s with no pause control.
**Fix:** a *scoped* reduce block — stop the marquee and wrap the text statically, drop radar autoplay to manual stepping, keep the 0.12–0.15s color transitions. Do **not** use a blanket `0.01ms` kill; it would destroy useful feedback and freeze the ticker mid-scroll with text clipped out of view.
**Command:** `/impeccable animate`

### [P1] PWA offline mode cannot render its two headline features
`sw.js` precaches the shell and bails on cross-origin, but index.html loads Leaflet 1.9.4 and Chart.js 3.9.1 from cdnjs. Offline, `L` and `Chart` are undefined — the radar map and the 48-hour chart both fail. For a product whose README leads with offline PWA support, the two main visual features are the ones that don't survive it. Vendoring them locally (~200KB) also removes a third-party dependency from a self-hosted appliance.
**Command:** `/impeccable optimize`

### [P1] Four timers run forever with no visibility guard
30s age/debug render (app.js:803, network), 60s heartbeat (:4374), 30s offline/debug (:4414), and the main refresh (:3586, 30s in storm mode). Zero `visibilitychange` or `document.hidden` guards in app.js — while `admin.js:296` already has them, so the pattern is in the repo and simply absent where it matters. Worse, `renderTimeline()` runs on the 30s loop and rebuilds the entire list, but `#timeline-section` is `data-default-collapsed` — the app rebuilds a hidden DOM subtree every 30 seconds indefinitely, polling a Raspberry Pi from a phone in someone's pocket.
**Command:** `/impeccable optimize`

### [P1] Admin "Test All" structurally cannot report a failure
Verified: `testAllProviders` counts `passed++` inside a try and `failed++` in a catch, but `testProvider` swallows every error in its own catch (admin.js:749) and never rethrows. `failed` is always 0, so the summary always reads `✓ N passed` even when every individual result span shows `✗`. An operator's one-click validation gives false reassurance.
**Fix:** return a boolean from `testProvider` and count on it.
**Command:** `/impeccable harden`

## Minor Observations

- Every page load can fire up to six **red error toasts** saying the app updated: `sw.js:47` posts SW_UPDATE on every successful revalidation of every static asset, and app.js:128 routes it to `showError()`. Routine cache behavior pollutes the severe-error channel.
- `#alert-count` counts viewport-filtered alerts while the ticker uses all effective alerts — **pan the map away and the badge reads 0 while the ticker still screams.**
- `PWS_NAMES = {KOKPRAGU20:'ZNewHouse', KOKPRAGU2:'ZOldHouse'}` — the author's own station nicknames are hardcoded in shipped source (app.js:67). Every other user sees raw station IDs, with no settings field to change it.
- Sidebar Sunrise/Sunset/UV are permanently `--` unless OpenWeather is configured, while the Astronomy panel 300px away shows real values from `/astro`. Two sources of truth, one always empty.
- Celsius mode is half-metric: pressure always returns inHg; PWS cards hardcode `in`, `°F`, and `inHg`.
- Configured timezone is honored in exactly one render path (with a literal `TODO`); everything else, **including alert expiry times**, uses browser locale.
- `.badge { background: var(--danger) }` applies to every badge, so the Astronomy day-of-week chip renders as a red alert badge.
- `navigator.clipboard` is undefined on plain http over a LAN — the default self-hosted Pi deployment — so "Copy Token" throws silently and the one-time-visible token is lost.
- Revoked agent tokens can never be deleted (Delete is disabled when revoked); the list grows unbounded.
- The admin unsaved-changes guard excludes API keys and passwords, but `markUnsaved` fires on them — the indicator and the exit guard disagree.
- The admin Save bar is `position: sticky; top: 0` but placed *after* all nine provider cards, so it's invisible for the first ~2000px of scroll.
- `admin.html` is ~90% inline styles: 147 inline `style=` attributes, `rgba(255,255,255,0.05)` repeated 20+ times with no class. The dashboard and the admin page look like two products.
- No `min-width` query and zero `clamp()` calls exist — on a 4K wall display the sidebar stays 220px and labels stay 9px, which is the stated use case.
- Every live rule uses `px` on a `html { font-size: 13px }` base, so browser font-size preferences are ignored entirely; fixed-height chrome then clips any text scaling.

## Questions to Consider

1. The badge counts alerts in the map viewport; the ticker counts all monitored alerts. Which one is the product's answer to "am I in danger" — and why should panning a map change how many warnings you have?
2. Should a home dashboard mint its own hazard index ("Storm: Elevated") and give it the same visual authority as the National Weather Service, with no explanation anywhere?
3. If the product's thesis is "my station vs. the official station," why is the default **Auto Blend** — a silent merge whose precedence rules appear in no help page, tooltip, or UI?
4. NWS ships the sentence that saves lives on every warning. What reasoning produced nine metric tiles, a retry-pressure meter, a cache-hit readout, and an ops timeline — and not that one paragraph?
5. If the phone is where the alerts arrive, why is it the least capable client you ship?
6. Who is the System Status panel for, in a viewer whose user wants to know if it will rain?
7. Everything about the layout persists; nothing about the data does. What made those two categories different, and does the user know?
8. Tides and METAR are configurable providers with no rendering surface. Is the roadmap "add features" or "answer questions"?
